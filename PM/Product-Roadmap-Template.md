# Product Roadmap — Reusable Template *(AI-era)*

> **How to use this template**
> A modern roadmap is a **decision system, not a delivery schedule.** It communicates *where we're headed and why*, organized by outcomes — not a dated list of features.
> - **PART A — Core**: fill in for every roadmap.
> - **PART B — Extended**: deeper planning, dependencies, and communication views.
>
> **Why this template is built for the AI-coding era**
> AI-assisted development (Copilot, Cursor, agents, "vibe coding") has collapsed the gap between "we should build that" and "it's live." That changes roadmapping in concrete ways, baked into the structure below:
> 1. **Build is cheaper; being right is not.** AI makes it cheap to ship the *wrong* thing fast — so discovery, prioritization, and clear outcomes matter **more**, not less.
> 2. **Plan in outcomes + bets, not dates.** Each initiative states the outcome, the **assumptions** that make it right/wrong, and a **review date** — a decision system, not a Gantt chart.
> 3. **Estimate by confidence & reversibility, not hours.** When code is fast to produce, the scarce resource is *judgment*. Size items by confidence and how reversible they are, not effort alone.
> 4. **Carry a quality/health lane.** AI-generated code can raise defects & security findings (~1.7×) without governance — keep tech health on the roadmap, not as an afterthought.
> 5. **Two user types now:** humans via UI *and* AI agents via API/MCP. Note agent-readiness where relevant.
>
> **General rules:** organize by **themes → outcomes**; use **Now / Next / Later (+ Trash)**; it's a **living document** — revisit on a set cadence. Delete this block and italic *prompts* once written.
